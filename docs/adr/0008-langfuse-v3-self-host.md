# Langfuse v3 self-host: шість контейнерів замість одного

## Context and Problem Statement

Бриф вимагає трейси й вартість на інцидент — дерево supervisor → agent → tool. Langfuse
self-host у compose виглядав очевидним вибором, і спершу взяли v2 заради одного
контейнера з postgres.

Виявилось, що SDK Langfuse v2 написаний під `langchain.callbacks` з LangChain 0.x, якого
в LangChain 1.x немає взагалі. «Легкий варіант» тут не існує як опція.

## Considered Options

* **Langfuse v2 self-host** — один postgres, але SDK несумісний з LangChain 1.x, на якому
  побудований увесь проєкт.
* **Langfuse Cloud** — нуль контейнерів, але трейси інцидентів їдуть назовні; для демо на
  синтетиці прийнятно, для будь-чого далі — ні, і це зайва звичка.
* **Без трейсингу, тільки логи** — ріже пункт брифу, який називає KPI «вартість на
  успішно розібраний інцидент»; без трейсів цю цифру нема звідки взяти.
* **Langfuse v3 self-host** — шість контейнерів (postgres, clickhouse, redis, minio,
  worker, web), але сумісний SDK і повне дерево трейсу локально.

## Decision Outcome

Chosen option: «Langfuse v3 self-host». Вибір вимушений сумісністю, а не перевагами: v2
просто не працює з нашим стеком.

Трейсинг при цьому **не має права ламати інцидент**: `agents/observability.py` загортає
ініціалізацію в try і мовчки вимикається, якщо сервера немає. Агент працює далі без
трейсів, а не падає.

### Consequences

* Good, because дерево трейсу і вартість на інцидент доступні локально, без виходу назовні.
* Good, because `session_id = thread_id` — інцидент видно цілим деревом, а не набором
  незв'язаних викликів.
* Bad, because стенд виріс до 16 контейнерів, і на слабкій машині це помітно.
* Bad, because шість контейнерів заради спостережуваності — непропорційно для демо;
  якщо різати, це перший кандидат, і `LANGFUSE_ENABLED=0` це вміє.
