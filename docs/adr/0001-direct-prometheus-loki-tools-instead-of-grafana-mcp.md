# Прямі HTTP-тули до Prometheus і Loki замість Grafana MCP

## Context and Problem Statement

Бриф вайбатону називає Grafana MCP інструментом, який «закриває 80% tool-шару»: через
нього агент мав ходити і в Prometheus, і в Loki, і за alert rules. Але два інші пункти
того ж брифу вимагають несумісного з цим: Context-Minimization (у промпт ідуть факти, а
не сирі дані) і офлайн-евали на записаних виводах тулів, без піднятого стенду.

MCP-сервер віддає відповідь джерела як є. Одна вибірка з Loki — це сотні рядків, тобто
і дорогий контекст, і недовірений текст, по якому прилітає prompt injection. І кожен
прогін евалів тягне за собою живий стенд.

## Considered Options

* **Grafana MCP на весь tool-шар** — відповідає брифу дослівно, але сирі відповіді
  ламають Context-Minimization, а офлайн-прогін датасету стає неможливим.
* **Grafana MCP плюс власний шар стиснення поверх нього** — зберігає MCP, але додає
  проксі-шар, який робить рівно те, що робив би власний тул, плюс залежність від
  окремого процесу в кожному прогоні евалів.
* **Прямі HTTP-запити з власними тулами, MCP лише там, де він унікальний** — тул сам
  вирішує, що віддати моделі; єдиний вихід у мережу легко підміняється у тестах.

## Decision Outcome

Chosen option: «Прямі HTTP-запити з власними тулами», бо стиснення виводу має відбуватись
**до** того, як його побачить модель, а це властивість тула, не транспорту. `query_loki_patterns`
віддає топ-N патернів з лічильником і трьома прикладами замість 2000 рядків;
`query_prometheus` — агрегати ряду замість 120 точок.

Grafana MCP лишається кандидатом на annotations, alert rules і panel images — там, де
він справді дає те, чого немає в прямому API.

### Consequences

* Good, because евали бігають офлайн і відтворювано: увесь модуль має один вихід у
  мережу (`_get`), і тести підміняють саме його.
* Good, because у промпт фізично не може потрапити сирий лог — це властивість коду, а не
  дисципліни; на це є тест `test_raw_log_lines_do_not_reach_the_model`.
* Bad, because відхилення від брифу треба щоразу пояснювати суддям.
* Bad, because дублюється частина того, що MCP уже вміє — при зміні API Prometheus
  ламатись буде наш код, а не чужий сервер.
